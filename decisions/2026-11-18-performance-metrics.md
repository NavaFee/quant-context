# 绩效指标与结果 JSON 口径

## 背景
T-75 的绩效计算与结果导出需共享统计单位、不可计算值和时间口径；T-78 固化契约。

## 决定
- 以 positions.qty 的 0→正→0 为完整轮次，部分买卖归入同轮；净盈亏包含双边费用，滑点已在成交价中。末尾未完成轮次不计胜率、PF 和 trade_count，trades 保留全部成交。
- trade_count 计完整轮数；持平轮次计入胜率分母；PF 按盈利/亏损轮次的净盈亏汇总，无亏损为 null，仅亏损为 0。
- 八项数值指标允许有限 number 或 null，trade_count 为非负整数；数值不接受 bool，null 仅用于这八项，界面显示“—”；非有限输入和溢出报错。
- 年化按首末收盘估值历时与 365 天；相邻权益收益不补首根零值，波动取 ddof=1；Sharpe=A/V、Calmar=A/abs(D)，无风险利率为 0，公式与边界见 product.md。
- meta 为整数 UTC 毫秒 [首根开盘,末根开盘+周期)，equity.ts 沿用开盘时间；缺口不补数据，空 bars 拒绝导出；保留原有 JSON 字段与数组结构。

## 放弃的方案
- 按每次卖出或成交笔数统计：部分平仓会改变统计单位。
- 用 0 代替未定义指标：无法区分真实零值；使用 NaN/Infinity 不符合严格 JSON。

## 影响
- quant-engine 与 quant-web 按 product.md 校验和展示；现有有限数字类型仍合法，消费者需正确处理 null。
- 下游采用后回滚时，先回退相关导出，再回退本契约扩展；本决策不实现引擎或界面。
